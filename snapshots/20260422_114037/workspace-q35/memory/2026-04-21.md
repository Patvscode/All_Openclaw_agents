## SetStack — Workout Tracker v3.3
- **Volume tracking** — total lbs per exercise across all workouts, shown in Progress view as horizontal bars + per-exercise mini charts. Shows peak volume workout.
- **PR celebration** — animated overlay with emoji when you beat a personal record (higher weight or same weight + more reps). Fires once per exercise per workout.
- **Warm-up calculator** — button in Today header. Enter working weight → calculates 3 progressive warm-up sets (50%, 70%, 85%).

- **Stats in Progress view** — added PR count and peak volume stat cards alongside total workouts/sets/weekly goal.
- **Version bump** to v3.3 in settings footer.

## SetStack — Data Flow Notes
- Exercise log keys: `YYYY-MM-DD` → `{ exercises: { [exIdx]: [{done, weight, reps, rir}, ...] }, completed, startTime, endTime }`
- Workout logs (separate history): `getWorkoutLogs()` returns sorted array with date, planName, routineName, exerciseCount, totalSets, startTime, endTime
- Previous workout lookup: `getPreviousExerciseData(exerciseName)` searches logs sorted by date for matching exercise name, returns {weight, reps}
- Previous set lookup: `getPreviousSetData(exerciseName, setIndex)` same but returns data for specific set index

## Hive — Multi-Model Swarm Pattern (In Progress)
- **Discovery:** research-engine's capacity.py ported to hive/core/capacity.py — dynamic parallelism based on model + system state
- **Key insight:** capacity = min(RAM-limited, GPU-limited, safety-buffer). KV cache scales with layers × kv_heads × head_dim × context
- **GPU throughput degrades linearly per parallel slot:** small models (0.8b) support 20-50 workers, medium (4b) 8-16, large (30b+) 3-5
- **Role classification:** WORKER_ROLES = {grunt: [0.8b, phi3, 2b], vision: [llava, 4b, gemma3:4b, gemma4:2b], orchestration: [30b, flash-nothink], transcription: [0.8b, 2b]}
- **OllamaWorker supports swarm mode:** parallel prompts via `prompts` config array, runs all in parallel via asyncio.gather, returns combined results
- **Registry needs swarm routing:** per-capability provider configs need swarm_parallel parameter and capacity-aware selection
- **Files to create/modify:**
  - `hive/core/swarm_orchestrator.py` — new: orchestrates multi-model swarms, uses capacity calculator
  - `hive/workers/ollama_vision.py` — new: dedicated OllamaVisionWorker class (registry references it but it doesn't exist yet)
  - `hive/config/registry.yaml` — update with swarm_parallel params, fix missing ollama_vision imports
  - `hive/core/capacity.py` — add swarm-aware routing (WORKER_ROLES already defined)
  - Dashboard UI in `hive/api/static/app.js` — model selector dropdown, capacity display
- **Current blockers:** ollama_vision worker class missing from registry (references hive.workers.vision.ollama_vision.OllamaVisionWorker which doesn't exist); ollama_worker.py is a catch-all that should be split
